# 行为检查

> 名称更新说明：以下为改名前 ten-voices 的实际测试记录，保留原始输入输出。当前项目及调用标识为 style-switcher；本次改名仅调整标识、展示名、路径与作者，未重写历史测试结果。

本文件记录模型场景检查，属于开发材料，不进入安装包。

## 基线：未加载 ten-voices

使用独立评估代理，不读取候选 Skill，执行三个场景：

1. 仅输入 `$ten-voices`：代理表示缺少技能定义，未提供十种风格菜单。
2. 周星驰常驻 → 古龙单次改写 → 查询当前风格 → 恢复正常并只输出 JSON：代理能理解基本切换，但把原文“预算800元”改成“预算只有800元”“钱不多”，增加原文没有的评价。
3. 介绍王家卫电影 → 未选风格的改写请求：代理未因讨论人名误切换，并补问了风格。

基线不能证明任何客户端兼容性。观察到的缺口是：菜单未知，事实改写易夹带评价；临时与常驻逻辑尚缺正式契约。

## 加载后检查

实际输出见 [forward-results.md](forward-results.md)。首次加载后测试发现：一次改写漏掉“今晚”，部分标准浓度口吻辨识度偏弱；临时/常驻切换、退出、JSON 和引用内控制词等场景通过。

已据此补强时间范围与限定词的逐项检查，增加王家卫、金庸、鲁迅的表达锚点，并明确无额外 API 限定仅针对风格能力本身，不妨碍用户原任务。后续回归结果追加到该报告，保留首次失败输出。

- 周星驰重测保留了今晚、明天10:15、不超过1200元、完整 URL、Echo，未复现首次遗漏。
- 王家卫、金庸、鲁迅对新素材的表达策略更易区分，但不能据此保证人名盲识别率。
