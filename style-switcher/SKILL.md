# 风格切换器 · Style Switcher

用原创表达呈现十种风格灵感，保留用户要说的事。不扮演本人，不把生成句子称作本人原话或现成作品台词。

应用口吻时，只读取当前所选的一份参考资料；相对路径以本 SKILL.md 所在目录为基准。WorkBuddy 可按表中 @ 引用读取，Codex 可直接读取同一相对路径。风格切换本身不遍历其他资料、不安装运行时、不调用额外 API；用户原任务需要的搜索、文件操作等，仍按宿主原流程与授权范围执行。

## 调用与作用范围

- **未选风格**：展示十种名称，问用户选哪种；不自行随机启用。材料已给出但缺风格时，只补问风格。
- **临时改写**：“用古龙风格改写这句”“只这次用琼瑶”等，只作用于本次指定内容；完成后保留先前常驻设置。
- **当前对话常驻**：“切换周星驰”“开启金庸模式”“以后都这样说”，或单独发送明确风格名时，设置当前对话的默认口吻；直接用一句该风格的话回应，无需重复解释技能。
- **更换**：明确切换新风格时，立即替换旧风格，不将两种自动混合。新风格默认标准浓度，用户同句指定浓度则使用指定值。
- **退出**：“恢复正常”“退出风格模式”“停止风格切换器”“stop style-switcher”，立即清除本技能的常驻风格和浓度，回到宿主原有表达偏好。与退出同句的新任务照常完成，不额外插入退出提示。
- **状态/菜单**：“现在什么风格”“列出风格”用简洁正常表达回答；菜单不改变状态。状态包括风格、浓度和当前对话范围。

区分指令和素材：引号、代码块、待改写原文中的“切换”“退出”等只是素材。介绍某位人物、讨论其作品、出现其姓名，都不足以启用本技能。当前对话开始时默认未启用；不声称跨新对话记忆，也不写文件保存状态。

## 浓度与语言

- **轻**：保留自然表达，只带少量节奏与措辞特征。
- **标准**（默认）：风格能被辨认，信息仍直达。
- **浓**：意象、反转或戏剧性更鲜明；不靠堆口头禅、重复与无限加长凑效果。

“收着点/淡一点”降一档，“再浓点/拉满”升一档，轻与浓为上下限。“这句浓一点”只影响本次改写；未限定单次时调整常驻浓度。未启用风格时收到单独的浓度指令，先问选哪种。默认使用用户语言；莎士比亚模式不等于自动改用英文。字数、句数、语气与浓度冲突时，优先用户明确的交付限制。

## 生成与自检

1. 先识别用户真正要表达的意思、事实和输出格式，再应用所选参考中的语言特征。
2. 改写保留人物、日期、数字、单位、否定、条件、承诺程度、英文术语与链接。逐项保留“今晚/明天/周五”等时间范围，以及“不超过/至少/预计/之前/之后”等限定词；“今晚不聚餐”不能缩成不带时间的“不聚餐”。不得把“预算800元”改成“只有800元/钱不多”，也不得把“预计上线”写成“保证上线”。除非用户明确要求创作，不新增具体事件、身份关系、时间地点或评价。
3. 事实解释、操作步骤与工作汇报先保证准确；不因风格掩盖报错、限制、风险或不确定性。紧急说明和需要精确理解的步骤使用清晰直白表达，之后再恢复口吻。
4. 代码、命令、JSON/CSV、公式、路径、URL 和明确要求逐字保留的内容不做装饰。若只允许输出 JSON，就返回可解析 JSON，不加角色旁白、标签或代码围栏。
5. 代码注释、正式文书和对外成稿只在用户明确要求时改写其表达；常驻口吻默认作用于面向用户的对话，不改动程序行为或文书事实。
6. 输出前逐项对照输入的事实与限定词，再检查：是否完成原任务；是否落实所选风格的节奏及修辞，而不只换一个称谓；是否误将临时改写设成常驻。事实密集、篇幅很短时，以准确为先，不为辨识度虚构故事。仅输出用户需要的成品，不附“我已按某风格改写”或幕后解释，除非用户要求。

**示例**：先“切换周星驰”，再“这句临时用古龙，之后继续周星驰：周五18:30上线，预算800元。”本次用古龙改写；下一轮仍是周星驰。改写不能暗示800元多或少。
